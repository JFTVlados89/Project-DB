**Цель работы:** *спроектировать и реализовать базу данных для выбранного профильного кейса, охватывающую все этапы: от анализа предметной области и карты данных до физической реализации, аналитических запросов и программного доступа*.

---

## Команда проекта и распределение ролей
* **Каменский Артем — Роль: Аналитик**
  * Выбор датасета и анализ предметной области.
  * Нормализация данных, выделение сущностей (минимум 8 таблиц) и проектирование связей.
  * Составление карты данных (`data_map.md`) и классификация атрибутов (152-ФЗ, коммерческая тайна, открытые данные).
  * Разработка DDL-скрипта (`schema.sql`) с настройкой ограничений и первичных индексов.
  * Проектирование матрицы доступа (`access_matrix.md`) и формирование требований к защите информации.
  * Написание 6-8 аналитических SQL-запросов (`queries.sql`), включая запросы с JOIN, CTE и оконными функциями, а также создание витрины данных (`MATERIALIZED VIEW`).

* **Якушев Максим — Роль: Администратор / Teamlead**
  * Разработка серверного кода: написание бизнес-функций или процедур на PL/pgSQL.
  * Создание триггеров: триггеры проверок (например, бизнес-логики) и триггеры аудита для журналирования изменений в формате JSON (`triggers_functions.sql`).
  * Сбор и анализ подробной статистики по использованию таблиц (самые частые и ресурсоемкие запросы).
  * Написание DCL-скриптов (`roles.sql`) для создания ролей БД и настройки прав доступа на уровне схем и таблиц.
  * Координация проекта, управление GitHub Projects и проведение Code Review.

* **Бурмагин Олег — Роль: Разработчик**
  * Отрисовка физической модели БД в виде ER-диаграммы (`er_diagram.png`).
  * Написание Python-скриптов (`db_access.py`) для подключения к БД (psycopg / SQLAlchemy) и выполнения параметризованных запросов.
  * Реализация транзакций, batch-загрузки данных и выгрузки витрин в pandas DataFrame.
  * Проверка качества загружаемых данных (поиск дублей, пропусков).
  * Проведение профилирования и оптимизации: выполнение `EXPLAIN ANALYZE` для 5 ресурсоемких запросов (до и после создания индексов) и применение партицирования.

## Структура репозитория

```text
/
├── docs/
│   ├── analysis/
│   │   ├── data_map.md          # Описание предметной области и карта данных
│   │   ├── access_matrix.md     # Матрица доступа и требования к защите
│   │   └── data_flow.png        # Схема потоков данных
│   └── diagrams/
│       └── er_diagram.png       # ER-диаграмма
├── sql/
│   ├── schema.sql               # DDL-скрипт (таблицы, ограничения, индексы)
│   ├── seed.sql                 # Тестовые данные (или Python-скрипт генерации)
│   ├── queries.sql              # Аналитические запросы
│   ├── triggers_functions.sql   # Функции, процедуры, триггеры
│   └── roles.sql                # DCL-скрипты (роли, GRANT/REVOKE)
├── python/
│   └── db_access.py             # Скрипт подключения и выгрузки данных
├── README.md                    # Описание проекта, результаты EXPLAIN ANALYZE
└── report.pdf                   # Пояснительная записка
